# Issue #7 — audit and security test plan

Scope: [Check on security implementation](https://github.com/engjw/lta_assignment/issues/7). Tests and documentation only; production implementation follows the user's reviewed failing-test commit (§8).

| Requirement | Plan and contract | Actual red-run result |
| --- | --- | --- |
| R-6.4 | Attach `audit: {sourceFile, sourceRow, ingestedAt}` to every accepted event: basename, one-based physical starting line including the header, UTC ISO instant captured during ingestion. Keep duplicates distinct, preserve metadata through search/cap/list/detail, and expose it in details. | 11 backend audit cases fail: metadata is absent. Two Angular display cases fail; exact duplicate selection after JSON round-trip also fails. |
| R-6.1 | Retain existing validation/dataset coverage. Add a forged multiline log-value case: reject it, continue ingestion, emit one structured diagnostic without raw input or internal paths. | Existing 102 CSV cases and the new log-injection case pass. | R-6.2 | Retain four-field detail escaping tests. Add hostile list UUID/type bindings, audit-source text and safe popup handoff. Guard production Angular source against HTML/sanitiser bypasses. | Existing rendering tests pass. New list binding/handoff and source-policy checks pass; audit-source display fails because the field is absent, not because an exploit executed. |
| R-6.3 | Keep the ADR's dev-only stance. Require explicit `dev` for anonymous startup; default, `prod`, and `prod,dev` must fail without production authentication. Full identity/admin-role integration remains a closure plan. | Three startup-denial cases fail because the application starts; explicit dev startup passes. These tests do not prove an authenticated admin workflow. |
| R-6.5 | Check current production sources/configuration for private-key/provider-token signatures and literal credential assignments; never print matched secret values. Future credentials must be external. | Two scoped regression checks pass. This is not a full repository-history secret scan. |
| R-6.6 | Real HTTP tests for malformed JSON/types/dates, invalid UUID/page, missing resources, unsupported methods and unexpected service failures. Public JSON contains only `code` and `message`; use `BAD_REQUEST`, `NOT_FOUND`, `METHOD_NOT_ALLOWED`, or `INTERNAL_ERROR` with appropriate HTTP status and a generic message. No stack/path/version fields or identifying server headers. | All 12 cases fail. Current responses use Spring's default envelope; negative pagination returns 500 rather than 400. No claim that every current response leaks a stack trace. |

Audit UI timestamps use `DD MMM YYYY HH:mm:ss UTC`. Cached audit values must match the API event, including ingestion time; stale or changed references return to event selection. Seven of the ten new Angular cases already pass; three are red. Audit metadata identifies a source event within an ingestion, not a durable URL/database key. The 2,000-result history limitation remains unchanged.

When implementing the startup guard, local launch/Docker configuration will need to activate `dev` explicitly. No production identity provider is selected by these tests.

Full run: **Maven 158 tests: 132 pass, 26 fail, 0 errors/skipped. Angular 60 tests: 57 pass, 3 fail.** All previous 127 backend and 50 Angular tests pass. New tests compile successfully; the failures are behavior assertions. Assertions after each first failure remain unverified. The backend includes unit, context and HTTP integration tests because startup policy and error dispatch cannot be established by isolated controller mocks.

Run from `starter/apps/api`: `mvn test` (Java 21). Run from `starter/apps/web`: `npm test -- --progress=false` with Chrome available. This run used the existing Maven Java 21 Docker image and headless Chrome; logs are in ignored `target/issue-7-security-red.log` and `.angular/issue-7-security-red.log`. After strengthening the audit fixture to reorder events before capping, reran its 11 cases: all still fail on missing audit metadata, with no errors/skips (`target/issue-7-audit-red.log`).

Review and manually commit these tests on `issue-7-security-check` before implementing the missing controls. Passing these checks will not certify all security, benchmark performance, or implement the deferred production identity integration.
